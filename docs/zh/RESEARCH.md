## 定位与选题

**CapPrune：基于球冠分块剪枝的精确余弦检索**，是面向不可变稠密向量集合的 CPU 研究与工程库。我希望优化过程能够被检查：跳过一个块应当有数学理由，变慢的场景也应当保留在证据中。目标用户是研究精确检索的工程师、为近似索引构建正确性基准的研究者，以及维护中小型本地向量集合的开发者。

依据已检查的 Apple M1 Pro 主机、16 GiB 统一内存、可用 CPU 工具、不可用的 Docker 运行时，以及失败的模型站点访问，比较了三个方向：

| 方向 | 研究与工程价值 | 可行性与实验成本 | 决策 |
|---|---|---|---|
| 投机解码 | 保持分布的采样、草稿与目标模型验证、调度；已有 [Leviathan 等人的工作](https://arxiv.org/abs/2211.17192)。 | 有意义的模型级证据需要适配的模型对与推理运行时；当前环境的模型下载不可靠。 | 不用仅验证采样的小示例宣称模型规模收益。 |
| KV Cache 分配与复用 | 内存所有权、碎片与服务并发；[PagedAttention](https://arxiv.org/abs/2309.06180) 是已有参考。 | 有价值的服务级结论需要推理引擎集成与代表性设备工作负载，集成成本会占据本次交付的大部分工作。 | 不纳入本版本。 |
| 精确余弦检索 | 几何上界、确定性 top-k、数据布局、数值可靠性，以及与优化稠密计算的测量比较。 | 可在已检查的 CPU 上运行，无需模型下载；合成分布解释机制边界，依赖附带的真实数值数据提供非合成场景。 | 选定：一个上界、一种索引、三条可比查询路径。 |

范围是有限、非零实数向量上的余弦 top-k，内部归一化为 float64。它不等同于任意未归一化向量的最大内积检索：归一化会改变后者的问题。当前索引不可变。GPU 算子、近似搜索、在线增删、稀疏向量、文本嵌入生成、向量数据库服务，以及应用级相关性结论均不在范围内。

## 研究问题与冻结验收

**问题：** 保守球冠分块剪枝在什么条件下能够保持精确余弦 top-k，同时降低相对于连续 BLAS 扫描的单线程 CPU 延迟？

**假设：** 紧凑、分离的簇允许拒绝大量完整分块。高维各向同性数据形成较宽且重叠的球冠；较小集合则没有足够向量计算量抵消 Python 调用、上界和候选合并开销。增大 k 可能推迟剪枝。构建成本使该机制更适用于多次复用同一索引的场景。

机器可读的唯一基准是[测量前协议](../../configs/protocol.json)。以下为目标，不是结果：

| 类别 | 冻结声明 |
|---|---|
| 主要 Target | 在 `clustered_n50000_d64` 上，相对 float64 连续扫描的单查询中位延迟加速至少 **1.5 倍**。 |
| 辅助 Target | 同场景平均实际计算向量比例不超过 **30%**。 |
| 正确性验收 | 每个评测工作负载与扫描路径的有序行号完全一致，分数满足 `atol=1e-12, rtol=1e-12`。 |
| 主要工作负载 | 50,000 个向量、64 维、64 个生成簇、高斯噪声 0.035、k=10。 |
| 测量预算 | 请求 1 个 BLAS 线程、种子 20260921、每场景 40 个查询、7 轮重复、4 个预热查询、6 次聚类迭代。 |
| 覆盖范围 | 聚类数据 5k/50k 个向量、64/128 维、k=10/100；50k×64 各向同性数据；真实数字数据 1,757×64，40 个留出查询；32×8 且 k=N。 |
| 功能验收 | 可导入 API、三种搜索模式、稳定同分排序、拒绝非法输入、可复用与持久化索引、离线演示、CLI、测试、锁定构建及自动生成的结果。 |

实测结论位于 [EXPERIMENTS.md](EXPERIMENTS.md) 和原始结果文件。未达标的目标仍应记录为未达标。预期减少分数计算量是机制假设，不代表延迟必然下降。

已安装的 NumPy 使用 Apple Accelerate。在导入 NumPy 前设置 `VECLIB_MAXIMUM_THREADS=1`，同时设置 OpenBLAS/OMP 线程选项，以请求冻结的单线程配置。当前主机上 `threadpoolctl` 无法直接检查 Accelerate 的实际运行线程数，因此证据证明的是**请求一个线程**，而不是已验证实际生效线程数。两条路径使用相同后端和配置；引用硬件相关结果时须保留这一限制。

## 数学定义

集合包含 N 个 d 维向量。每个非零输入行归一化为单位向量 x_i，查询归一化为 q。返回 k 个原始行号，按分数

$$
f(i)=q^\top x_i
$$

降序排列；计算分数相同时按原始行号升序排列。B 表示非空块数，C 表示请求的聚类中心数。球面 k-means 将每一行分配给内积最大的中心，再将各非空簇中向量的和归一化为新中心。迭代时遇到空簇或向量和恰好抵消为零，则保留上一轮中心；最终均值为零的块选择其首个成员作为球冠方向。这是一种划分启发式，不保证全局最优。正确性不依赖聚类目标足够好：较差的簇只会削弱剪枝。

对于块 j，取单位中心 c_j 及下界

$$
s_j\leq\min_{i\in j}c_j^\top x_i.
$$

所有成员均位于由 c_j 和 s_j 定义的闭球冠中。记 a_j=q^\top c_j，则整个球冠上的上界为

$$
U(a,s)=
\begin{cases}
1,&a\geq s,\\
as+\sqrt{\max(0,1-a^2)}\sqrt{\max(0,1-s^2)},&a<s.
\end{cases}
$$

对于精确单位向量，`max(0, ·)` 在数学上多余。实现将角度输入截断到 [−1, 1]，并使用代数等价且更稳定的因式形式 `sqrt((1-a)*(1+a))` 与 `sqrt((1-s)*(1+s))`。

### 上界为何成立

令 alpha=arccos(a)、theta=arccos(s)，二者均属于 [0, pi]。球冠成员与中心夹角不超过 theta。由角距离的三角不等式，angle(q, x) 至少为 max(0, alpha−theta)。余弦在 [0, pi] 上单调递减，所以最大分数不超过 cos(max(0, alpha−theta))。当 alpha≤theta 时，球冠包含 q，最大值为 1；否则由余弦差角公式得到第二个分支。这一推导是已有角度 branch-and-bound 几何的特例，不要求 s 为正。超过半球的球冠仍然有效，但通常无法带来有效剪枝。在 a≥s 时错误地使用第二分支会产生不正确的结果。

按 U 降序访问分块，并维护已找到的最佳 k 个候选。只有候选数达到 k，且某块的保守上界**严格小于**当前第 k 名分数时，才允许跳过该块。相等时仍需搜索，因为未访问的同分向量可能拥有更小行号。后续块的上界不更大，所以满足这一严格条件时可以终止遍历。每个被扫描的块都计算真实向量分数，结果中不使用估计分数。

### 浮点约定

上述证明基于实数运算。实现使用 float64 归一化和内积，以 `64 * eps * d` 向下放宽 s、向上放宽 a，最后对上界增加向外余量并使用 `nextafter`。接近 ±1 时，平方根具有较强敏感性，仅在最终分数上添加极小 epsilon 并不充分；放宽球冠与角度输入用来处理这一失败模式。先缩放再归一化避免有限极端幅值的上溢/下溢。零向量、NaN、无穷大、维度不匹配及非法 k 均显式拒绝。

实际承诺是采用该剪枝算法的精确搜索，以及所声明的 float64 一致性验证。这不等于对所有 BLAS 实现和对抗性 IEEE-754 输入给出形式化区间算术证明，有限测试也无法证明更强的声明。不同稠密内核的微小运算差异还可能改变数学上近似相等分数的顺序；报告的一致性相对于统一 float64 基线与已声明的同分规则。[代码导读](WALKTHROUGH.md) 将公式和保护措施对应到实际实现。

## 不变量与复杂度

关键不变量包括：每个原始行恰好属于一个非空块；布局变换保留原始行号；所有存储向量与中心满足归一化约定；各球冠包含对应块并保留数值余量；候选数达到 k 前不进行剪枝；所有返回候选都已显式计算分数。持久化验证应重新构造或核验这些不变量所需的信息，不能直接信任任意文件中保存的上界。

I 次聚类迭代的分配成本为 O(I N C d)。分配分数矩阵按配置的字节预算分块；这限制分配矩阵的临时空间，不代表限制进程总内存。索引保留原始及重排后的 float64 向量，仅两份数组就占 **16Nd 字节**；此外还有 O(N) 行号/偏移、O(Bd) 中心及其他数组。这样的重复存储让基线与分块路径可直接比较，但不是内存压缩。

查询以 O(Bd) 计算 B 个上界，以 O(B log B) 排序，并以 O(Md) 为 M≤N 个向量计算分数。`_topk` 使用部分选择，保留分界处全部同分项后再按字典序排序。对于 m 个候选，通常成本为 O(m+k log k)，但全部同分时为 O(m log m)。访问 V 个块时，通常选择/合并工作量为 O(M+Vk log k)；最坏同分情况将排序工作增加到 O((M+Vk) log(N+k))。最坏情况下不保证次线性：可能扫描全部块，在 O(Nd) 之外还存在选择开销。显式 `blocked` 模式访问同一布局但不剪枝，从而将上界作用与布局、逐块调度开销分开。

若优化查询更快，则预计构建成本的摊销点为

$$
Q_{\text{break-even}}\approx T_{\text{build}}/(T_{\text{scan}}-T_{\text{pruned}}).
$$

这一条件估计计入包括归一化在内的完整索引构建成本，不扣除单独扫描所需的准备成本，因此在这些假设下较为保守。分母非正时，不存在有利摊销点；不得把它描述为实测端到端应用结果。并发吞吐与大批量 GEMM 属于冻结单查询 API 实验之外的工作负载。

## 负面结果能够说明什么

实际计算比例低却延迟较差，意味着上界、top-k 合并或调用开销超过了省下的矩阵向量计算。实际计算比例高，意味着分区几何缺乏选择性。合成数据表现好而真实数据弱，说明收益限于有利分布。查询更快但构建昂贵，则说明用途偏向反复复用索引的场景。这些结果分别指向不同的后续问题：更紧或层次化的上界、更低调用开销、自适应扫描回退、更省内存的存储，或者不同的划分目标。它们是未来研究问题，并非已实现功能。
